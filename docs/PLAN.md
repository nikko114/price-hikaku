## 0. ひとことで

いろんなお店（イオン、業務スーパー、ドラッグストア…）で見た「値段」と「量」を記録して、
**単価（100gあたり◯円 ／ 100円で◯g）にそろえて比べる** Web アプリ。
iPhone の「ホーム画面に追加」でアプリのように使う。データはすべて iPhone の中に保存（サーバーなし）。

- 仮の名前: **単価くらべ**（ホーム画面に出る名前。あとで変更可）
- 公開先（予定）: https://nikko114.github.io/price-hikaku/

### 使う場面

1. **買い物中に記録** — 値札を見て「＋記録」→ お店は現在地から自動で選ばれる → 値段と量を入れて保存（同じ店で続けて記録できる）
2. **棚の前で判定** — 値段と量を入れた瞬間に「🎉 過去最安！」「⚠️ 割高：〇〇店のほうが安い」が出る（保存しなくても OK）
3. **家で振り返り** — 商品ページでお店ランキングと価格推移グラフを見る／買い物リストで「どの店で何を買うか」を決める

## 1. 基本方針

| 方針 | 理由 |
|---|---|
| 素の HTML / CSS / JavaScript（ES Modules）。フレームワーク・ビルド・npm 依存なし | ファイルを置くだけで動く。React なし |
| オフラインで完全に動く（Service Worker） | スーパーの店内は電波が弱いことが多い |
| データは端末内だけ（localStorage ＋ 写真は IndexedDB） | サーバー不要・プライバシー |
| 外部通信は「周辺のお店検索」（OpenStreetMap）だけ。設定で OFF 可 | 位置情報を外に出す場面を最小にする |
| iPhone の片手操作が前提の UI（下タブ、大きいボタン、数字キーボード） | 店の通路で使うため |

## 4. 単価の計算ルール

### 4.1 量の種類と単位

商品ごとに「量の種類」と「比べる単位」を決める（最初の記録で入力した単位から自動で推定、あとで変更可）。

| 量の種類 | 入力できる単位 | 比べる単位（初期値） | 例 |
|---|---|---|---|
| 重さ | g, kg | 100g | 肉、米、野菜 |
| 容量 | ml, L | 100ml | 牛乳、飲料、洗剤 |
| 長さ | m | 1m | トイレットペーパー（2倍巻きも公平に比べられる）、ラップ |
| 個数 | 個・枚・本・袋・ロール・組・食・回分 | 1個 | 卵、ティッシュ、カップ麺 |

### 4.2 計算式

- 総量 = 内容量 × 単位換算 × 入数　例) 500ml × 6本 = 3,000ml、70g × 4個 = 280g
- 税込価格 = 税込で入力したならそのまま、税抜なら 値段 × (1 + 税率)（途中では丸めず、表示するときに丸める）
- **円/量** = 税込価格 ÷ 総量 × 比べる単位 →「100gあたり ¥64.4」
- **量/円** = 総量 ÷ 税込価格 × 100 →「100円で 155g」

例) 税抜 298円・500g・税率 8% → 税込 321.84円 → **100gあたり ¥64.4** ／ **100円で 155g**

### 4.3 税率

- 比較はすべて税込でそろえる（本体価格が大きく書いてあるお店でも、見たまま税抜で入力できる）
- 税率はカテゴリから自動（食品 8%、お酒・日用品 10%）、商品ごとに変更可
- 記録には「その時の税率」も保存（あとで商品の設定を変えても過去の計算が変わらない）
- 税込/税抜の選択は、お店ごとに前回の入力を記憶

### 4.4 比較と判定

- お店ランキング: **各お店の最新の通常価格（特売を除く）** を安い順に並べる。特売価格は併記
- 古い記録（初期 60日以上前）は「古い」マーク付きで薄く表示
- 記録シートのリアルタイム判定:

| 条件 | 表示 |
|---|---|
| 過去のどの記録よりも安い | 🎉 過去最安！ |
| 他店の最新価格の最安以下 | ✅ いちばん安い |
| 他店の最安 +5% 以内 | 🙂 ほぼ最安 |
| それより高い | ⚠️ 割高：〇〇店のほうが ¥x 安い（+y%） |
| 記録がまだない | 📝 はじめての記録 |

### 4.5 「同じ商品」の考え方

商品＝「比べたいもの」の単位。厳密に同じ商品（例: 明治おいしい牛乳）でも、ざっくり（例: 鶏むね肉）でも OK。
量が違っても単価に直すので比べられる。銘柄の違いは記録の「メモ」に残す。
商品名を入力するときは似た名前の既存商品を候補に出して、重複登録を防ぐ。

## 5. 位置情報でお店をサジェスト

### 5.1 流れ

1. 記録シートを開く
   - 位置情報がすでに許可されていれば、自動で現在地を取得
   - 許可されていなければ「📍 現在地からお店を探す」ボタンを表示（押したときだけ許可を聞く）
   - iOS のホーム画面アプリは起動のたびに位置情報の許可を聞かれることがあるので、勝手には聞かない
2. **登録済みのお店**を距離順に表示（半径 300m）
   - いちばん近い店が 150m 以内（大きい店は建物の中心から離れやすいため）、GPS の誤差が 100m 以下、
     2番目に近い店と 30m 以上はなれているときだけ自動選択（変更可）
   - 精度が悪い（屋内など）・紛らわしいときは自動選択しない
   - 2時間以内に記録したお店が選ばれていても、いま 500m 以上はなれていたら選び直してもらう
3. **周辺のお店（OpenStreetMap）** を表示 → タップで登録して選択
4. 位置が取れないとき: 直近 2時間以内に記録したお店を初期選択（同じ店で続けて記録するケース）

### 5.2 OpenStreetMap（Overpass API）での周辺検索

- 半径 500m のお店を検索（スーパー、コンビニ、ドラッグストア、業務用、百貨店・モール、100円ショップ、ホームセンター、八百屋・肉屋・魚屋、酒屋 など）
- 店名は `name` ＋ `branch` タグ（例: `イオン` ＋ `〇〇店` →「イオン 〇〇店」）、チェーン名は `brand` タグ
- 登録済みのお店（OSM の ID が一致、または 50m 以内の同名店）は候補から外す
- 公開サーバー3つ（private.coffee → overpass-api.de → VK Maps）に順番に問い合わせ、4秒返事がなければ次のサーバーにも聞く。
  429（混雑）を返したサーバーは30秒使わない（利用ルール）。最後に答えたサーバーを次回は最初に使う
- 結果は端末に保存して7日間使い回す（前に探した地点から150m以内）。つながらないときは60日前の結果まで使う
- 同時に Nominatim（OSM の場所検索）でも「supermarket / convenience store / chemist」を1秒おきに検索（利用ルール: 1秒に1回まで）。
  支店名・チェーン名は extratags / namedetails から取る。Overpass が全部だめでも、この3種類は見つかる
- 画面に「© OpenStreetMap contributors」を表示（ライセンス表記）
- 外に送るのは現在地の座標だけ。設定で OFF にできる

クエリのイメージ:

```
[out:json][timeout:10];
nwr["shop"~"^(supermarket|convenience|chemist|wholesale|department_store|mall|variety_store|doityourself|hardware|general|greengrocer|butcher|seafood|alcohol)$"](around:500,{緯度},{経度});
out center 40;
```

## 6. グラフ

- **依存なしの自作 SVG**（軽い、オフラインで確実に動く、ダークモードに合わせやすい）→ `js/chart.js`
- 色: お店ごとにカテゴリ8色（色覚の違いでも隣どうしが見分けられることを検証済みの並び。ライト/ダークで別の段）。
  色は「その商品で先に記録したお店」から順に固定し、期間や凡例の切り替えで塗り直さない。9店目からは灰色
- 線 2px・点 8px（背景色の 2px のふち）・特売は白抜きの点・目盛りは細い実線。軸は1本だけ
- タップ/なぞると、いちばん近い日に縦線が出て、その日の値段（値段が先、店名があと）をグラフの上に表示。キーボードの ←→ でも動く
- 「どのお店が安い？」は 2店以上で比べた商品だけ数える（1店だけの商品は「最安」とは言えないため）。1店しかなければ棒にせず文で
- 価格推移: 横軸＝日付、縦軸＝単価。お店ごとに色分けした線＋点、特売は★、点をタップでその記録の詳細、期間 3ヶ月/1年/全期間、凡例タップで表示切替
- お店比較: 横棒（最新単価のランキング）。最安を強調、各バーに単価と記録日
- お店の総合ランキング: 最安になっている商品数の横棒
- 円/量 ⇄ 量/円 の切替に追従

## 7. 商品の写真

- `<input type="file" accept="image/*">` → iPhone では「写真を撮る／写真ライブラリ／ファイルを選択」が出る
- Canvas で縮小して JPEG に再エンコード: 本体（長辺 1024px）＋ サムネ（長辺 200px）→ 1枚あたり 100KB 前後
- 写真の向きを補正。再エンコードで撮影位置などのメタデータは消える（バックアップを人に渡しても安心）
- 保存先は IndexedDB（次章）。一覧ではサムネだけ読むので軽い

## 8. データ保存とバックアップ

### 8.1 保存先

| データ | 保存先 | 理由 |
|---|---|---|
| 商品・お店・記録・設定 | localStorage（JSON） | 要望どおり。シンプル |
| 写真 | IndexedDB | localStorage は1サイト約5MBまでで、写真だと数十枚でいっぱいになる。IndexedDB も同じく端末内保存で、容量はずっと大きい |

- 容量の目安: 記録1件 ≈ 300バイト → 週20件を3年続けても約1MB。localStorage で足りる
- 保存に失敗したら（容量オーバー）警告を出す
- 読み書きは `js/db.js` に閉じ込めるので、将来すべて IndexedDB に移すのも簡単
- `navigator.storage.persist()` で「消さないで」とお願いする（効くかは iOS の判断次第なので、本命はバックアップ）

### 8.2 データ構造（案）

```js
// 商品
{ id, name: "鶏むね肉", category: "肉",
```

### 8.3 バックアップ

- **書き出し**: 写真込みの JSON 1ファイル（`price-hikaku-backup-2026-11-01.json`）→ iOS の共有シートで「"ファイル"に保存」・AirDrop・LINE など
- **読み込み**: 「置き換え」か「統合」（同じ ID は更新日時が新しいほうを採用）
- 30日以上バックアップしていなければ控えめにお知らせ

## 9. PWA（ホーム画面に追加）

- `manifest.webmanifest`: `name` / `short_name: "単価くらべ"` / `start_url: "./"` / `scope: "./"` / `display: "standalone"` / テーマ色 / アイコン（192・512・maskable）
- iOS 用: `apple-touch-icon`（180×180 PNG）、`apple-mobile-web-app-title`、ステータスバーの色、`viewport-fit=cover`
- Service Worker:
  - アプリ本体（HTML/CSS/JS/アイコン）を全部プリキャッシュ → オフラインでも起動
  - 新しいバージョンがあれば「更新があります [更新]」を出して切り替え
  - インストール時は HTTP キャッシュを通さずに取得して、更新が確実に届くようにする
- アイコンは SVG で作り、コンテナ内の Chromium で PNG に書き出す

iPhone のクセ対策:

- 入力欄の文字は 16px 以上（小さいとタップしたときに画面が勝手にズームする）
- 値段・量は `inputmode="decimal"` で数字キーボードを出す
- ホーム画面アプリにはブラウザの戻るボタンがない → 画面左上に「‹ 戻る」
- 下タブはホームバーと重ならないよう `env(safe-area-inset-bottom)` で余白
- ボタンは 44pt 以上、ダブルタップズームを無効化（`touch-action: manipulation`）

## 12. テスト方針

- 計算ロジック（単位換算・税・単価・判定・検索の正規化・バックアップの検証）は DOM に触らない純粋関数にして、`node --test` で単体テスト（追加インストールなし）

## 13. iPhone で気をつけること・リスク

| 項目 | 内容 | 対策 |
|---|---|---|
| データが別々 | Safari で開いたときとホーム画面アプリでは保存場所が別 | 最初からホーム画面アプリで使う。移行はバックアップで |
| 7日ルール | Safari は7日間使われないサイトのデータを消すことがある。ホーム画面アプリは独自に日数を数えるので、使っていれば消されない（WebKit の説明） | ホーム画面アプリで使う |
| データ消失全般 | 「履歴とWebサイトデータを消去」、端末の容量不足など | バックアップ＋リマインド |
| 位置情報の許可 | ホーム画面アプリだと起動のたびに許可を聞かれることがある | ボタンを押したときだけ取得 |
| 屋内の GPS 精度 | 大きい店の中だと数十〜数百 m ずれる | 距離順の候補から選ぶ。精度が悪いときは自動選択しない |
| OSM のデータ | 店が載っていない、名前が古いことがある | 手入力・名前の編集ができるように |
| バーコード | iOS Safari は標準 API が実質使えない | Phase 5 でライブラリ同梱を検討 |
